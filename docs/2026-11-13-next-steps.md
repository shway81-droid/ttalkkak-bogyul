## 다른 컴퓨터에서 시작하기

```bash
git clone https://github.com/shway81-droid/ttalkkak-bogyul.git
cd ttalkkak-bogyul
npm install
npx playwright install chromium
npm run serve     # http://localhost:4173
npm test          # 단위 검사 + 자료 검증 + 글꼴 검사
npm run e2e       # 브라우저 검사(약 7분)
```

- 짬짬이 자료를 다시 가져오려면 `npm run import` (처음에는 `.cache/jjam-classroom` 에 짬짬이 저장소를 받습니다). 이미 받은 사본 그대로 쓰려면 `node scripts/import-jjam.mjs --no-pull`.
- 화면 파일을 더하거나 빼거나 바꾸면 `npm run stamp` (서비스 워커 파일 목록·캐시 이름).
- 인물 사진은 세로 540px·화질 70 WebP 로 줄여 둔다(2026-11-14, 7.3MB → 3.4MB). `npm run import` 가 복사하며 줄이고, 따로 줄이려면 `npm run photos`(이미 작은 사진은 건드리지 않음).

## 미뤄 둔 작은 문제 — 2026-11-16 처리

1. **사진 출처 줄이 잘림** → 고침. 라이선스를 앞에 두고(`사진: CC BY-SA 3.0 · 저작자`) 두 줄까지 보이며, 묻는 동안에도 두 줄 자리를 비워 두어 출처가 나타날 때 사진 크기가 그대로(`js/activities/word.js`, `.person-credit`). 1280×720 에서 가장 긴 줄로 브라우저 검사.
2. **업데이트 때 사진까지 다시 받음** → 고침. `sw.js` 가 화면 파일(`ASSETS`, `CACHE`)과 인물 사진(`PHOTOS`, `PHOTO_CACHE`)을 다른 캐시에 담는다. 화면 파일은 전처럼 한꺼번에(`addAll`), 사진은 한 장씩 받아 실패한 사진만 빠지고, 화면을 열 때마다 빠진 사진을 마저 받는다. 사진은 cache-first(내용이 바뀌면 캐시 이름이 바뀜). `npm run stamp` 가 두 목록과 두 이름을 찍는다.
3. **가져오기 도중 실패** → 고침. 원본 사진 경로·파일을 먼저 모두 확인 → 임시 폴더(`.cache/import-stage`)에 자료·사진을 만들고 자료 검증 → 통과하면 사진 폴더를 통째로 바꿔 끼우고 자료 파일을 바꿔 넣는다. 자료 검증에 사진 원본 주소(위키미디어 공용, https)·같은 사진 파일·같은 원본·같은 인물·같은 사진 내용 검사를 더함. 같은 짬짬이 커밋(1b601fe)으로 다시 가져와 자료가 그대로인 것 확인.
4. **사진이 안 읽히면 빈 칸** → 고침. "사진을 불러오지 못했어요" 알림을 보이고 힌트를 저절로 연다.
5. **그리기 흔적** → 고침. 규칙 화면 준비물(prep) 코드·`.rules-prep`·backpack 아이콘을 뺐다. "끝까지 함께하면 ★"은 실제로 받쳐 주는 [모두 ★](이야기)에 맞춰 "모두 함께하면 ★"으로 바꿈(인사 패널·규칙·진행 대본).
6. **브라우저 검사 한 번 멈춤** → 원인 찾아 고침(2026-11-17).
   - 원인: 서비스 워커가 화면 파일을 stale-while-revalidate 로 내주며, 열 때마다 뒤에서 새로 받아 **같은 캐시 칸을 덮어썼다**. 한 페이지가 캐시에서 모듈을 읽는 사이 다른 페이지(또는 앞 페이지)의 덮어쓰기가 같은 칸에 닿으면, 그 요청이 응답 없이 끊긴다(`net::ERR_ABORTED`, CDP `canceled=true`). 모듈 하나가 빠지면 모듈 그래프 전체가 실패해 `#app` 이 빈 채로 남고, 콘솔 오류·pageerror 도 없다.
   - 근거: 첫 화면 4~6개를 거의 동시에 여는 재현(`.cache` 에 둔 임시 스크립트)에서 고치기 전 230번 중 9번 멈춤 → 서비스 워커를 끄면 150번 중 0번, 덮어쓰기만 빼면 150번 중 0번. e2e 에서는 0.4초만 열린 '인사' 검사 페이지 바로 뒤 '정답 창' 검사의 첫 화면에서 두 번에 한 번꼴로 멈췄고, 끊긴 파일은 늘 마지막에 불리는 `js/activities/*.js` 였다. 서비스 워커 안에 기록을 넣으면 타이밍이 바뀌어 잘 안 나타났다. Linux(CI)에서는 드러나지 않았다.
   - 고침: 화면 파일도 사진처럼 cache-first(`sw.js` 의 `cacheFirst(event, cacheName, key)`). 담아 둔 것이 있으면 그것으로만 답하고, 없을 때만 받아 담는다. 화면 파일이 바뀌면 캐시 이름이 바뀌어 새 서비스 워커가 새 캐시에 한꺼번에 받으므로, 열 때마다 다시 받을 필요가 없다(`npm test` 가 `npm run stamp` 를 잊으면 알려 줌). 고친 뒤 같은 재현 230번 중 0번, 전체 e2e 4번 모두 통과. `tests/sw.test.mjs` 에 "담아 둔 파일은 다시 받지도 덮어쓰지도 않는다" 검사를 더함.
   - 실제 교실에서도: 첫 화면을 연 직후 정답 창을 열거나(정답 창이 `dom.js`·`icons.js`·`live.js`·`pages.js` 를 함께 씀) 빠르게 새로고침하면 같은 일이 생길 수 있었다(흔하지는 않음, 새로고침하면 돌아옴). 고친 뒤에는 평소에 캐시를 덮어쓰지 않으므로 생기지 않는다.
   - 멈추면 원인을 볼 수 있게 `scripts/e2e.mjs` 가 페이지마다 콘솔 오류·실패한 요청·HTTP 오류·이동 기록을 최근 80줄 모아 두었다가 검사가 예외로 멈추면 찍는 장치는 그대로 둔다.
